# Lab5 文字习题：文件系统与并发

> 完成 [Lab5 实验](../lab5-fs-and-sync.md) 后做这些题。答案参考 lab5 文档的"六、思考题与参考答案"节和 `labs/answers/lab5-answers.md`。

## 习题 1：fd（文件描述符）的作用

操作系统用 fd 这个整数来代表"打开的文件"。请解释：
- fd 为什么是整数而不是指针？
- 内核怎么从一个整数 fd 找到具体的文件信息？（数据结构是什么）
- 同一个文件被 open 两次，会得到相同还是不同的 fd？为什么？

## 习题 2：管道为什么是"环形缓冲区"？

管道用环形缓冲区在两个进程间传数据。请回答：
- 为什么用"环形"而不是"线性"数组？
- 环形的 read_pos 和 write_pos 到达数组末尾时怎么处理？
- count 字段记录什么？为什么不直接用 (write_pos - read_pos) 计算？

## 习题 3：自旋锁 vs 睡眠锁

lab5 实现了自旋锁。请对比思考：
- 自旋锁在拿不到锁时干什么？这种方式有什么代价？
- 自旋锁在单核 CPU 上为什么可能出问题？多核呢？
- "睡眠锁"（拿不到就让出 CPU 等待）相比自旋锁有什么优缺点？什么场景该用哪个？

## 习题 4：数据竞争的成因

假设没有锁，两个进程同时执行 `count += 1`。请解释：
- `count += 1` 在 CPU 层面是几条指令？
- 这几条指令交错执行时，会出现什么问题？请举一个具体的交错例子。
- 锁是怎么避免这个问题的？

## 习题 5：fork 继承 fd 与管道引用计数

fork 后子进程会继承父进程的 fd 表。请回答：
- 为什么子进程要继承 fd？（shell 的管道命令怎么靠这个工作）
- 管道的 fd 为什么需要引用计数，而普通文件的 fd 不需要？
- 如果不维护引用计数，管道的资源什么时候会泄漏？
