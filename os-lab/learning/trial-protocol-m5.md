# M5 试用方案（成员 A · 第 10–12 周）

## 目标问题

1. 工作台 + 证据导师是否降低「只追退出码」的错误完成？
2. Trap/调度可视化（若已上线）是否提高「为何 A→B」解释正确率？
3. 提示阶梯是否降低直接要答案，同时不显著增加挫败？

## 设计（最小可运行版）

- **人数**：理想 12–30；不足则 ≥5 可用性 + 1 名教师/助教专家走查。
- **对象 Lab**：Lab2（必选）；有余力加 Lab3 阅读+检查点。
- **对照**（若可行）：一半学生用纯 Markdown 手册路径，一半用引导式工作台；记录先验（是否学过 OS）。
- **禁止**：把相关性写成因果；样本量写入所有图表。

## 测量

| 指标 | 收集方式 |
| --- | --- |
| 首次 verified 时间 | runs.started_at / finished_at |
| 提示依赖 | hint_requested 次数、最高 hint level |
| 直接要答案率 | guardrail / category=direct_answer |
| 迁移题 | 课后 2 题（见 lab2/checkpoints.md）盲评 0/1/2 |
| 延迟测 | ≥3 天后 3 道短题（trap 路径、yield≠exit、断言意义） |
| 主观负荷 | 3 题 Likert（可选） |

## 分析模板

1. 描述统计 + 失败案例至少 3 个（负担增加 / 可视化误解 / 量规不稳）。
2. 不报告「显著提升」除非有预注册对比与足够 n。
3. 输出一份《试用修订记录》：改了文档/任务/导师策略/量规的哪一条，前后差异。

## 伦理与隐私

- 最小化采集；导出脱敏；试用结束后可应要求删除账号数据。
- 成绩若课程使用，系统分不得自动作为最终成绩（教师终审）。
