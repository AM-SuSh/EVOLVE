# EVOLVE · AI 交互过程评分方案（详解版）

> **一句话**：看学生「怎么跟 AI 学」，不是看「AI 有没有把题做对」。  
> 输出一个 0–100 的分数：`aiInteraction`（AI 交互过程分）。  
> 文献出处标在各节末尾；实现落点：`learning/` + 现有 `event-v2` 事件。

---

## 0. 先建立直觉（不看公式也能懂）

### 我们想奖励什么？

| 好的学习方式（高分） | 差的学习方式（低分） |
| --- | --- |
| 先说出自己的观察或假设，再问 AI | 把整道题/整段手册贴给 AI：「直接给我代码」 |
| AI 给提示后，自己去改代码、跑实验 | AI 一给答案就复制，从不运行验证 |
| 跑挂了 → 带着报错/现象再问 | 同一句「给我完整实现」连发很多遍 |
| 报告里写清：我判断了什么、AI 提醒了什么、我怎么验证的 | 只写「AI 帮我做完了」 |

### 我们不评什么？

- **不评**实验断言有没有全过（那是原来的「结果分 result」）。  
- **不评**聊了多少句（多聊不加工分，灌水也不加）。  
- **不评**AI 回复写得漂不漂亮（评的是学生行为）。

### 分数长什么样？

最终只有一个主分，由 **4 个维度**加权得到，再减去护栏扣分：

```text
aiInteraction = 0.30×提问质量Q + 0.30×轨迹形态T + 0.25×证据跟进E + 0.15×元认知M − 护栏扣分
```

每一维都是 0–100。下面从「系统怎么一步步算」讲起。

---

## 1. 评分流水线（共 6 步）

把一次 Lab 里学生与 AI 的记录，按固定顺序处理：

```text
① 收集原始记录
      ↓
② 给每条学生消息打标签（编码）
      ↓
③ 给整段对话判定「轨迹类型」+ 负面/正面标记
      ↓
④ 分别算出 Q、T、E、M 四个 0–100 分
      ↓
⑤ 加权合成 aiInteraction，减去护栏扣分
      ↓
⑥ （可选）LLM 再给一个「建议分」——默认不进最终成绩
```

教师看到的应是：总分 + 四维明细 + 轨迹类型 + 扣分原因 + 可点开的证据。

---

## 2. 第①步：收集哪些记录？

评分输入 = 该学生、该 Lab、该会话下的**学习事件**（已有 `event-v2`）。

| 事件类型 | 白话含义 | 评分里干什么用 |
| --- | --- | --- |
| `student_message` | 学生对 AI 说的话 | 算提问质量、轨迹 |
| `ai_response` | AI 的回复 | 判断「给过提示/拒过答案」之后学生有没有跟进 |
| `guardrail_triggered` | 触发护栏（如硬要完整答案） | 扣分 |
| 可信运行 / `verification_attempt` | 学生点了编译、测试等 | 算「有没有验证」 |
| `diagnostic_opened` | 点开了编译错误并跳转 | 算证据消费 |
| `trace_inspected` | 看了 Trace 回放 | 算证据消费 |
| `reflection_submitted` / 报告反思 | 学生写的复盘 | 算元认知 |

**重要**：运行必须是**本账号、本会话**产生的；不能拿别人的 run 凑证据。

---

## 3. 第②步：给每条学生消息打标签

每条 `student_message` 先变成结构化标签，再计分。  
标签设计主要来自论文 **2405.19132**（新手程序员 ChatGPT 对话编码）。

### 3.1 标签一：意图 —— 是不是在「要完整答案」？

| 标签 | 含义 | 在本系统怎么判定 |
| --- | --- | --- |
| **SR**（Solution Request） | 明确索要完整解/完整代码 | `category === 'direct_answer'`，或护栏判定为要答案 |
| **non_SR** | 概念、现象、原因、对比、探索等 | `concept` / `phenomenon` / `cause` / `comparison` / `exploration` |

**例子**

| 学生原话 | 标签 |
| --- | --- |
| 「直接把 `task.rs` 的完整实现给我」 | SR |
| 「我观察到只有 1 次 Yield round，是不是 current 没更新？」 | non_SR |
| 「trap 进入后 sepc 应该指向哪？」 | non_SR |

### 3.2 标签二：跟进类型 —— 这句话在对话里扮演什么角色？

来自 2405.19132 的 Follow-up 分类：

| 标签 | 含义 | 简单判定规则 |
| --- | --- | --- |
| **STA** | 独立开一个新问题 | 会话第一条，或与上一题明显换题 |
| **PRE** | 接着自己上一句往下挖 | 「那如果…」「还有…」承接自己的问题 |
| **RES** | 回应 AI 的上一句 | 「按你说的我改了 XX，但还是…」 |
| **COR** | 纠正/收窄上一轮（含纠自己或纠 AI） | 「我刚才说错了，其实是…」「不是要代码，我想问…」 |

**为何重要**：全是 STA（东问一句西问一句）不如 PRE/RES/COR 多（在同一问题上迭代）。

### 3.3 标签三：解题步骤 —— 这条消息在解决哪类问题？

来自 2405.19132 的 Issue 类目（我们只用常用几类）：

| 标签 | 含义 | 典型说法 |
| --- | --- | --- |
| **PU** | 理解题目/任务 | 「这题要我改哪里？」 |
| **CU** | 概念理解 | 「协作调度和抢占有什么区别？」 |
| **CG** | 要生成代码 | 「把函数写出来」→ 常与 SR 重叠 |
| **DE** | 调试 | 「报错是这个，可能哪错了？」 |
| **RA** | 运行/现象分析 | 「输出只有 task0，说明什么？」 |
| **OT** | 其他 | 闲聊、无关 |

可先用现有 `category` 粗映射，不够再加关键词：

| 现有 category | 默认 Issue |
| --- | --- |
| concept / comparison | CU |
| phenomenon | RA |
| cause / exploration | DE 或 RA |
| direct_answer | CG + SR |

### 3.4 什么叫「有效消息」？

- 连续**重复粘贴同一段** → 只算 1 条。  
- 为防刷屏：编码与统计时**最多取前 30 条**有效消息；第 31 条及以后**不加分也不额外扣「话多」分**（但不豁免护栏扣分）。

## 4. 第③步：整段对话的「轨迹类型」和标记

论文 **2604.10400** 指出：要看**整段 prompt 序列**像什么学习方式，而不是把每句话分数加起来。  
我们把一段 Lab 对话归成 **5 类轨迹**（先用规则树，不必上复杂聚类）。

### 4.1 五类轨迹（决定 T 维的「底分」）

| 轨迹类型 | 学生实际在干什么 | 底分 T₀ |
| --- | --- | --- |
| **FullDelegation 全委托** | 大部分是 SR；几乎不跟进；几乎不跑实验 | 15 |
| **OneShotAdopt 一击采纳** | 只聊 1–2 轮就要答案；然后不再验证 | 25 |
| **HybridScaffold 混合脚手架** | 有概念/调试问；也采纳部分提示；有至少一次运行 | 70 |
| **IterativeRefine 迭代精炼** | 多轮 PRE/RES/COR；以 DE/CU 为主；出现过失败再成功 | 90 |
| **EvidenceDialogue 证据对话** | 非 SR 为主，且消息/报告里引用了输出或 run/trace | 95 |

### 4.2 怎么判定轨迹？（决策顺序，从上到下，命中即停）

```text
1. 若 SR 比例 ≥ 70% 且 从未可信运行
      → FullDelegation

2. 若有效消息 ≤ 2 且 存在 SR 且 从未可信运行
      → OneShotAdopt

3. 若（引用了 run/trace/关键输出）且 SR 比例 < 40%
      → EvidenceDialogue

4. 若（跟进类 PRE+RES+COR 占比 ≥ 40%）
   且（DE 或 CU 类消息 ≥ 2）
   且（存在失败运行后再次提问，或失败后再通过）
      → IterativeRefine

5. 若（有至少一次可信运行）且（存在 non_SR 消息）
      → HybridScaffold

6. 否则
      → 更接近 OneShotAdopt 或 FullDelegation
        （SR 比例 ≥ 50% → FullDelegation，否则 OneShotAdopt）
```

### 4.3 三个特殊标记（加减分用）

来自论文 **2407.00305**（CS1 学生把整题扔给 AI、很少验证）：

| 标记 | 何时打上 | 对分数的影响 |
| --- | --- | --- |
| **WHOLE_TASK_DUMP** | 某一条（尤其首条）基本是整段任务说明 + 意图为 SR | 提问质量 Q 再减 20 |
| **ADOPT_NO_VERIFY** | AI 已给出较具体步骤/代码暗示后，**15 分钟内**没有任何可信运行/验证事件 | 轨迹分 T 再减 25 |
| **VERIFY_LOOP** | 出现过「提问 → 运行（可失败）→ 再提问」 | 轨迹分 T 再加 10（上限 100） |

## 5. 第④步：四个维度分别怎么算？

下面每个维度都给出：**含义 → 公式 → 手工演算例子**。

---

### 5.1 维度 Q：提问质量（权重 30%）

**评的是**：问得好不好——少要完整答案、多重跟进、问题类型多样、多深问。

先算四个比率（分母都是「有效消息数」N，N≥1；若 N=0 则 Q=0）：

| 符号 | 含义 | 计算 |
| --- | --- | --- |
| `SR_rate` | 要完整答案的比例 | SR 条数 ÷ N |
| `deep_rate` | 深问比例 | category 属于 `cause` / `comparison` / `exploration` 的条数 ÷ N |
| `follow_rate` | 跟进对话比例 | PRE+RES+COR 条数 ÷ N |
| `issue_diversity` | 解题步骤种类数 | 不同 Issue 标签个数，**最多按 5 计** |

**公式：**

```text
Q_raw = 100
        − 40 × SR_rate
        + 35 × deep_rate
        + 15 × follow_rate
        + 4  × issue_diversity

若第 1 条有效消息就是 SR：     Q_raw = Q_raw − 15
若有 WHOLE_TASK_DUMP：         Q_raw = Q_raw − 20

Q = 把 Q_raw 限制在 0～100 之间
```

**为什么这样设计？**

- 减 SR：要完整答案越多越低（2405.19132）。  
- 加深问：why / 对比 / 探索更高（Graesser 深层提问思想）。  
- 加跟进：说明在对话里推进，不是一次性甩题。  
- 加多样性：既问概念又问调试，比只会一种好。  
- 首条就 SR、整题粘贴：额外惩罚（2407.00305）。

#### 演算示例 A（问得较好）

有效消息 4 条：

1. non_SR, cause, DE, RES  
2. non_SR, exploration, DE, PRE  
3. non_SR, concept, CU, PRE  
4. non_SR, phenomenon, RA, RES  

则：

- N=4，SR 条数=0 → `SR_rate=0`  
- deep（cause/comparison/exploration）=2 条 → `deep_rate=0.5`  
- 跟进=4 → `follow_rate=1`  
- Issue 种类={DE,CU,RA} → `issue_diversity=3`  

```text
Q_raw = 100 − 0 + 35×0.5 + 15×1 + 4×3
      = 100 + 17.5 + 15 + 12
      = 144.5
Q = 100（封顶）
```

#### 演算示例 B（问得很差）

有效消息 3 条全是 SR + CG，全是 STA，首条 SR，且 WHOLE_TASK_DUMP：

- `SR_rate=1`，`deep_rate=0`，`follow_rate=0`，`issue_diversity=1`

```text
Q_raw = 100 − 40×1 + 0 + 0 + 4×1 = 64
再 −15（首条 SR）−20（整题倾倒）= 29
Q = 29
```

---

### 5.2 维度 T：轨迹形态（权重 30%）

**评的是**：整段对话更像「请 AI 代做」还是「借 AI 迭代思考」。

**公式：**

```text
T = 该会话轨迹类型的底分 T₀

若有 VERIFY_LOOP：     T = min(100, T + 10)
若有 ADOPT_NO_VERIFY： T = max(0, T − 25)
```

#### 演算示例

| 情况 | 计算 | T |
| --- | --- | --- |
| IterativeRefine + VERIFY_LOOP | 90+10 | 100 |
| HybridScaffold + ADOPT_NO_VERIFY | 70−25 | 45 |
| FullDelegation | 15 | 15 |

文献：**2604.10400**（轨迹）、**2407.00305**（不验证就采纳要罚）。

---

### 5.3 维度 E：证据跟进（权重 25%）

**评的是**：对话有没有落到「真跑、真看错、真回看证据」上。  
（对应 2407.00305：很多学生拿到 AI 答案后不验证。）

先看四个开关（是/否）：

| 开关 | 含义 | 得分 |
| --- | --- | --- |
| `has_run` | 本会话至少 1 次**可信**运行 | +35 |
| `has_fail_then_pass` | 先有未通过，后有通过（同 Lab） | +25 |
| `cited_evidence` | 消息或报告里出现 `run:` / `trace:`，或明确引用了一段真实输出 | +20 |
| `diag_or_trace` | 至少点开过诊断或 Trace | +20 |

**公式：**

```text
E = 上面命中项的分数相加（满分 100）

特殊封顶：若 has_run 为假（从没可信运行过）
         则 E = min(E, 40)
```

也就是说：**光聊天、从不运行，证据分最高只能到 40。**

#### 演算示例

| 情况 | 计算 | E |
| --- | --- | --- |
| 跑过 + 失败后再通过 + 看过 Trace | 35+25+20 | 80 |
| 只看过诊断、从未运行 | 20，但无 run → min(20,40)=20 | 20 |
| 跑过但一次过、无引用、无 Trace | 35 | 35 |

---

### 5.4 维度 M：元认知（权重 15%）

**评的是**：反思里能不能说清「我 / AI / 验证」三分工（对应现有反思要求，并呼应好的学习复盘）。

看反思文本里三类信号是否出现（关键词或等价表述即可）：

| 信号 | 例子 |
| --- | --- |
| `self` 独立判断 | 「我原来以为…」「我的判断是…」 |
| `ai_role` AI 角色 | 「导师提醒我去看 yield…」 |
| `verify` 验证 | 「用 lab2 断言 / 输出 Yield round×5 验证」 |

**公式：**

```text
若没有反思事件： M = 0

若有反思：
  M = 20
    + 28（若有 self）
    + 26（若有 ai_role）
    + 26（若有 verify）
```

三类全有 → M = 20+28+26+26 = **100**。  
只有「AI 帮我写完了」→ 通常只有 `ai_role` → M = 20+26 = **46**。

---

### 5.5 护栏扣分

与现网一致：

```text
penalty = min(25, 5 × 护栏触发次数)
```

触发 1 次扣 5；最多扣 25。

## 6. 第⑤步：合成总分

```text
aiInteraction = round(0.30×Q + 0.30×T + 0.25×E + 0.15×M − penalty)
再限制到 0～100
```

### 完整算例 1：认真迭代的学生

假设：

- Q=100，T=100（IterativeRefine+VERIFY_LOOP），E=80，M=100，penalty=0  

```text
aiInteraction = 0.30×100 + 0.30×100 + 0.25×80 + 0.15×100
              = 30 + 30 + 20 + 15
              = 95
```

### 完整算例 2：甩题不验证的学生

假设：

- Q=29，T=15（FullDelegation），E=20（无 run 封顶前较低），M=0，护栏触发 2 次 → penalty=10  

```text
加权 = 0.30×29 + 0.30×15 + 0.25×20 + 0.15×0
     = 8.7 + 4.5 + 5 + 0
     = 18.2
aiInteraction = round(18.2 − 10) = 8
```

### 完整算例 3：会聊也会跑，但爱要答案

假设：有效消息 5 条，其中 2 条 SR；有 HybridScaffold；跑过但无失败再成功；反思三类齐全；护栏 1 次。

粗算：

- `SR_rate=0.4`，`deep_rate=0.4`，`follow_rate=0.6`，`issue_diversity=3`  
- 首条非 SR，无整题倾倒  

```text
Q_raw = 100 − 40×0.4 + 35×0.4 + 15×0.6 + 4×3
      = 100 − 16 + 14 + 9 + 12 = 119 → Q=100
```

（深问和跟进够高时，中等 SR 仍可能把 Q 顶满——若实践中偏松，可在校准阶段把 SR 系数从 40 调到 50；见 §10。）

更保守的手算若 deep_rate 只有 0.2：

```text
Q_raw = 100 − 16 + 7 + 9 + 12 = 112 → Q=100 仍封顶
```

为示范「中等生」，改用：Q=70，T=70，E=35，M=100，penalty=5：

```text
加权 = 0.30×70 + 0.30×70 + 0.25×35 + 0.15×100
     = 21 + 21 + 8.75 + 15 = 65.75
aiInteraction = round(65.75 − 5) = 61
```

## 7. 这个分如何进入课程总分？

os-lab 原来大致是：

```text
总分 = 0.45×过程分process + 0.35×结果分result + 0.20×反思分reflection
```

**推荐接法（两阶段）：**

**阶段 A（先并行、好解释）**

```text
过程分process = 0.55×旧过程启发式 + 0.45×aiInteraction
结果分、反思分不变
```

**阶段 B（稳定后）**  
用 Q/T 逐步替换旧过程里的「提问质量/深度」等子项，避免两套逻辑长期并存。

**必须分开显示：**

| 分数 | 含义 |
| --- | --- |
| `aiInteraction` | 借 AI 学习的过程质量 |
| `result` | Lab 断言是否通过（实验对不对） |
| `reflection` | 反思写作（可与 M 部分重叠，报告时注明） |

论文 **2504.14928 EducationQ** 的启示：对话过程好 ≠ 知识/任务已掌握，所以**交互分高但断言没过，总分仍应被 result 拉低**。

## 8. 第⑥步（可选）：LLM「建议分」——默认不进成绩

当规则分难以刻画「思考深度」时，可以用大模型按清单打建议分。  
方法来自 **2503.06424**（二元量规 + 总分）和 **2601.08654 RULERS**（必须锁量规、贴证据、再校准）。

### 8.1 六个是非题（每题必须摘一句学生原话或 runId）

| 题号 | 问什么 | 答「是」需要什么证据 |
| --- | --- | --- |
| B1 | 是否用自己的话陈述过假设/机制？ | 学生消息摘录 |
| B2 | 是否有过非「要完整答案」的概念或调试问？ | category 或摘录 |
| B3 | AI 给可行动提示后，是否跟进（改代码或追问）？ | 时间序 + 可选 run |
| B4 | 是否出现「失败运行 → 再对话」？ | run 序列 |
| B5 | 是否较少在无证据时索要完整答案？ | SR 率、护栏记录 |
| B6 | 反思是否区分我 / AI / 验证？ | 反思摘录 |

模型先列证据，再给 1–5 的 `llm_suggest`。  
**无摘录 → 该题记「未观察到」，不得凭空「是」。**

### 8.2 与最终分的关系

```text
最终成绩默认 = 规则算出的 aiInteraction
llm_suggest 仅显示给教师，或在人工复核后由教师写入 teacherOverride
```

## 9. 系统应输出什么？（给学生/教师看）

```json
{
  "aiInteraction": 61,
  "Q": 70,
  "T": 70,
  "E": 35,
  "M": 100,
  "penalty": 5,
  "trajectoryType": "HybridScaffold",
  "flags": ["ADOPT_NO_VERIFY"],
  "breakdown": {
    "SR_rate": 0.4,
    "deep_rate": 0.2,
    "follow_rate": 0.6,
    "N_effective": 5,
    "has_run": true,
    "has_fail_then_pass": false
  },
  "summary": "有混合式提问且跑过实验，但存在不验证就采纳的迹象；反思完整。"
}
```

页面上建议展示为：

## 10. 实现时注意的坑

| 坑 | 正确做法 |
| --- | --- |
| 按「发言条数」加工分 | 禁止；只用比率与轨迹类型 |
| 自定义命令退出码 0 当验证 | 只有可信 recipe / 断言才算 `has_run` |
| 把 AI 是否讲对知识点算进学生分 | 不算；那是导师质检，不是学生过程分 |
| Q 公式封顶导致区分度不够 | 用 20 条人工轨迹校准 SR/deep 系数 |
| LLM 分直接当成绩 | 默认关闭；走教师复核 |

## 11. 落地顺序（仍然可实现）

1. **只做规则分**：编码 → Q/T/E/M → `aiInteraction`（不接 LLM）。  
2. 在报告页/教师页展示四维与轨迹。  
3. 人工标 20 条对话，调系数。  
4. 再考虑 LLM 建议分。  

验收最少 4 条：

1. 狂要答案 + 不运行 → 低分。  
2. 提问 → 跑挂 → 再问 → 跑通 → 高分。  
3. 复制粘贴刷屏 → 不明显高于正常对话。  
4. 用别人的 runId → E 不增加。

## 13. 速查卡片（贴墙上那一版）

```text
学生每条消息 → 打上：是否要答案(SR) / 跟进类型 / 解题步骤
整段对话     → 归成 5 类轨迹之一，并打上「整题倾倒 / 不验证采纳 / 验证闭环」
然后算：
  Q 提问质量 = 少要答案 + 多深问 + 多跟进 + 步骤多样 − 恶劣开局
  T 轨迹形态 = 轨迹底分 ± 验证相关标记
  E 证据跟进 = 跑过？失败再成功？引用证据？看过诊断/Trace？
  M 元认知   = 反思里有没有「我 / AI / 验证」
最后：
  aiInteraction = 0.3Q + 0.3T + 0.25E + 0.15M − 护栏扣分
```

**这就是全部评分逻辑。** 先实现这一页卡片；§8 的 LLM 层以后再说。
