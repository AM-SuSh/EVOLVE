# 入门指南

欢迎来到 **EVOLVE**。

本套系统对应的课程教材是 **[《操作系统导论》](/downloads/ostep-zh.pdf)**（*Operating Systems: Three Easy Pieces*，*OSTEP*）。

教材从三大方面组织整门课：**虚拟化（Virtualization）、并发（Concurrency）、持久性（Persistence）**。当然，学习操作系统只读懂书中理论还不够，更重要的是在理解理论知识的基础上把这些抽象投入实践，亲身体验和实现「从裸机到可用内核」这条路。本系统会按逻辑顺序，通过 Lab 带你搭起属于自己的操作系统；完成全部实验后，你将会获得对操作系统知识更深刻的理解，和一份完整能在 QEMU 上运行的个性化内核。

## 一、EVOLVE 是什么

EVOLVE 是一套面向操作系统课程的教学实验环境，也是一套 Web 教学平台。它的技术栈包括：

- **语言**：Rust
- **目标平台**：RISC-V 64（`riscv64gc-unknown-none-elf`）
- **运行方式**：在本机用 QEMU 模拟一台 RISC-V 机器，跑你自己的内核

《操作系统导论》里，程序之所以能「以为」自己独占 CPU、拥有一整片地址空间、还能读写文件，是因为操作系统提供了这些**抽象**。实验里你要做的，就是亲手把这些抽象逐步实现出来——而不是只在应用层调用它们。

EVOLVE 的核心设计是：**始终只有一个内核代码库**。通过 Cargo 的 feature 按阶段打开功能，让内核像搭积木一样逐步长出能力。你不用在多套互不相关的内核工程之间来回切换，更容易看清操作系统是怎样一层层长起来的。

平台把「引导式学习」和「AI 导师」做成完整闭环：

- **教师课程教学辅助**：创建班级和账号、按全局/班级/学生范围分发 Lab、布置报告格式、查看学习评价并完成验收。
- **学生自学使用**：学生登录后从当前 Lab 进入工作台，读手册、改代码、跑可信验证、问 AI 导师、写报告和复盘，形成可导出的成长证据链。
- **AI 导师辅助**：导师只提问和引导，不代替写代码，也不会在缺少真实验证证据时判定完成。

因此，EVOLVE 不只是静态实验文档，而是一个可以长期记录「判断、验证、排错、复盘」的学习平台。



## 二、你将完成什么

整条学习路径共 **8 个 Lab**，按系统构建逐层推进：

| Lab | 主题 | 对应教材主题（OSTEP） | 你将学到什么 |
|-----|------|----------------------|----------------------|
| Lab1 | 裸机启动与最小内核 | 导论基础：在「抽象」出现之前，机器如何跑起来 | 没有操作系统时，代码如何上电、如何输出、如何正常关机 |
| Lab2 | 中断处理与多任务 | **虚拟化（CPU）**：受限直接执行、陷入、上下文切换、调度入门 | 用户程序如何通过系统调用「请求」内核；多个任务如何轮流使用 CPU |
| Lab3 | 内存管理与虚存 | **虚拟化（内存）**：地址空间、分页与地址翻译 | 页帧、页表、地址空间：程序如何安全地使用「自己的那片内存」 |
| Lab4 | 进程管理 | **虚拟化（CPU）**：进程抽象与进程 API | `fork` / `exec` / `wait`：进程如何创建、替换与等待 |
| Lab5 | 文件系统与并发 | **持久性** + **并发**：文件与 I/O；锁与进程间通信 | 文件描述符与简单文件抽象、管道，以及内核中的自旋锁 |
| Lab6 | 磁盘文件系统 | **持久性**：文件系统实现、inode 与目录 | VirtIO 块设备、easy-fs 磁盘布局、硬链接与 `fstat`——文件真正落到「断电不丢」的磁盘上 |
| Lab7 | IPC 与信号 | **虚拟化（CPU）** 进阶：进程间通信与异步事件 | 统一 fd 抽象、`dup` 重定向、信号的注册/投递/屏蔽 |
| Lab8 | 线程与同步 | **并发**：线程、锁、条件变量与死锁 | 进程内多线程、阻塞式互斥锁/信号量/条件变量、银行家式死锁检测 |



## 三、平台操作指南

### 3.1 登录、注册与进入工作台

1. 打开 [引导式学习](/guide/ai-tutor)，或从站点顶栏的「引导式学习」入口进入；未登录时会先看到登录门。
2. 学生第一次使用选择「注册」，填写用户名或学号、密码，并从老师已创建的班级下拉框中选择班级；老师尚未创建班级时，注册页会提示先联系老师。
3. 已有账号直接登录。学生登录后，[引导式学习](/guide/ai-tutor) 会自动把你送回「当前应学习的 Lab」；教师账号进入同一入口，则会看到教师工作台的 Lab 列表。
4. 如果页面提示「教师尚未发布可学习的实验」，或工作台提示「当前实验尚未解锁」，先到顶栏「系统构建路径」查看该层写明的锁定原因（未分发、未到解锁时间、已截止或前置条件未完成），再请老师按范围分发。

### 3.2 工作台布局

进入 Lab 后，你会看到一个三区工作台：

| 区域 | 你看到什么 | 你应该在这里做什么 |
| --- | --- | --- |
| 左侧 | 实验手册 | 阅读学习目标、背景知识、任务、验证命令和思考题；目录可跳转，选中手册文字后可点「就此询问导师」 |

### 3.3 系统构建路径与「领取并开始」

顶栏常驻的「系统构建路径」展示 8 个系统层和期末探索任务。每一层都会显示：

- **当前状态**：待教师分发、等待开放、待完成前置、学习中、已发放 · 可回看、已学 · 可回看等。
- **下一步动作**：已解锁但未领取的层显示「领取并开始」；已开始或已学过的层显示「继续学习」「回到学习」「开始构建」。
- **证据状态**：是否已完成「运行验证」和「学习复盘」，以及累计的成长证据条数。
- **解锁/截止时间**：老师设置开放或截止时间后，这里会直接显示。
- **锁定原因**：未解锁的层会写明缺什么（例如「教师尚未手动分发该实验」「尚未到解锁时间」「任务已截止」「先完成上一层的可信验证并提交报告与复盘」），而不是只显示一个锁。

老师按范围分发后，学生需要在「系统构建路径」点击该层的 **「领取并开始」**，代码才会合并进自己的「我的系统」。升级只补必需的新文件，不会覆盖你已经写好的代码或自建用户程序。顶栏「我的系统 · labN」会与已发放的层同步；路径底部还可以「导出成长档案」。

### 3.4 一次 Lab 的标准操作

1. **先读手册，写出判断**：先找学习目标、前置知识、任务一/任务二、验证命令和思考题，再用自己的话写出「本 Lab 要实现什么机制、什么现象能证明它工作」。
2. **打开任务文件**：按手册列出的源码路径定位入口、待补全函数和调用点；文件状态徽章（A/M/T/G/!）可以帮助你区分新增、修改、待完成、生成和冲突文件。
3. **修改并保存**：修改代码后保存。保存只是把最新内容交给工作台和服务端，不代表实验完成；如果 Problems 出现编译、类型或借用错误，先处理这些诊断。
4. **运行可信验证**：优先使用当前 Lab 手册「验证」部分的命令。Lab1–Lab5 通常是 `cargo run -p kernel --features labN --release`，Lab6–Lab8 请用 `make test-lab6/7/8`。只有命令与当前 Lab 的可信验证命令一致时，这次运行才会被记录为可信 run；自定义命令成功运行不会伪造通过证据。
5. **查看测试结果**：对比断言里的期望值和实际值，检查关键断言和 Trace 统计。不要只看退出码 0，程序可能正常退出却没有触发关键路径。
6. **失败时先排查，再问导师**：按顺序检查命令是否与手册一致、feature 是否选对、Lab6–8 是否用 `make test-labN`、Problems 第一条诊断、测试结果第一条失败断言，然后带着判断和证据向 AI 导师提问。
7. **完成实验报告**：在学习支持区的「实验报告」页签里，用模板填写或切换到 Markdown 自由编写；可以插入图片和上传附件，预览后再提交给老师。
8. **完成苏格拉底复盘**：报告区会生成 3–5 个基于过程证据的问题，按「每题一页」作答；草稿会自动暂存，提交报告时正文、附件和复盘记录会一起提交。
9. **查看学习评价**：在「学习评价」页签生成或刷新评价，查看融合分、过程/反思分项和证据引用；没有观察到的项目会明确显示「未观察到」，不会伪造分数。
10. **领取下一层**：当前 Lab 完成可信验证，并把报告与复盘一起提交给老师后，等老师开放下一层，再到「系统构建路径」领取并开始；完成 Lab8 并提交报告与复盘，且老师已发布期末探索任务时，期末节点才会解锁。

### 3.5 如何使用 AI 导师

AI 导师是工作台右下角的悬浮窗口，它的证据条会显示三列：**当前阶段 / 已有证据 / 下一步所需**。

提问前可以先把证据附进对话（一次最多 5 段）：

| 来源 | 会附带什么 |
| --- | --- |
| 工作区 | 当前选区优先；没有选区时附光标附近代码片段 |
| 终端 | 终端选区优先；没有选区时附本次完整输出 |
| Problems | 全部诊断或单条诊断 |
| 测试结果 | 全部断言或单条断言 |
| 实验手册 | 选中文字后出现的「就此询问导师」，只附当前选段 |

好的提问通常包含三件事：**你的判断、真实证据、希望导师帮你判断的一个具体问题**。导师会按问题意图选择引导方式，并在直接索要完整实现时触发答案护栏；提示阶梯最高到 L4，仍不会替你写完整代码。

导师不会因为一句「退出码 0」就判定实验完成。没有真实可信 run、断言或 Trace 时，它不会声称你已经通过。

## 四、建议的学习方式

**首选：在[引导式学习工作台](/guide/ai-tutor)中完成每个 Lab。** 工作台把左栏手册、右栏工作区/学习支持和 AI 导师放在一起，按「定界 → 阅读 → 验证 → 排错 → 复盘 → 迁移」的闭环推进。导师只提问不代写；你的判断、可信验证、报告和复盘会被自动记录成可导出的学习证据链。

把每个 Lab 当成一个小闭环，按下面节奏完成：

1. **先对一下教材**  
   看本页表格里该 Lab 对应 OSTEP 的哪一块（虚拟化 / 并发 / 持久性），用书里的问题建立动机，再打开实验手册。

2. **读问题场景，对照代码**  
   文档里的图（启动流程、trap、页表、VirtIO、信号路径等）建议对着仓库源文件看一遍。

3. **跑通验证**  
   在工作台终端执行手册给出的验证命令。Lab1–5 可用 `cargo run -p kernel --features labN --release`；**Lab6–8 请用** `make test-lab6` / `test-lab7` / `test-lab8`（须 VirtIO，见各实验文档）。

4. **完成【任务二】阅读理解与思考题 / 小修改**  
   题目在各 Lab 实验手册【任务二】，完成后把自己的解释和验证证据写进报告与复盘。

5. **留下进度**  
   在工作台完成可信验证与苏格拉底复盘，再把报告与复盘一起提交给老师；老师开放下一层后即可领取，不需要等待教师逐次验收。

6. **善用 AI，但先自己想**  
   每个 Lab 文档末尾有「AI 提问模板」。提问时可以带上教材术语（如地址空间、系统调用、锁、死锁），效果通常更好。

遇到卡住时，优先检查：是否在正确的 Lab、feature 是否选对、验证命令是否与手册一致；Lab6 起还要确认是否用了带 VirtIO 的 `make test-labN`。
