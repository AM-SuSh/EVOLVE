# 引导式学习

<TutorEntry />

## 学生完整流程（照着走一遍）

1. **起服务**：`cd os-lab/handbook && npm run tutor`（保持运行，账号/终端/AI/代码功能都靠它）；
2. **注册/登录**：打开站点即进入登录页——首次使用点「注册」，填用户名、密码和**班级**；你的系统代码、学习进度与提交的报告都绑定账号（游客只读）；
3. **配模型**：右上角齿轮「模型设置」填接口地址/模型/Key（老师统一配置了就不用管，本机 Ollama 全留空即可）；
4. **领系统**：右上角「我的系统 · 未初始化」→ 初始化，领到 Lab1 最小骨架——从此终端和代码页签都指向你自己的系统；老师开放到哪一层，你才能升级到哪一层；
5. **学与做**：左栏读手册（「目录」按钮跳章节）→ 终端点「运行」跑通（成功自动记为验证）→ 「代码」页签阅读/编辑自己的实现（有 TODO 任务就补全，有 bug 就排错）→ 「把输出插入实验报告」；卡住时打开「AI 导师」页签提问（它只引导不代写）；
6. **写报告解锁**：实验报告面板按模板填写，「收获与反思」写完点保存——**一次成功运行 + 一次带反思的保存 = 解锁下一个 Lab**；
7. **升级系统**：解锁后回「我的系统」点升级，领下一层的必要代码（你已有的修改全部保留）；
8. **个性化（bonus）**：「我的系统」里登记自己的用户程序（如 `my_snake`），基于已学系统调用自由创作；
9. **交付**：报告面板点「提交给老师」（教师端直接可看，重复提交覆盖旧版）；也可「导出 md」留档、「导出成长档案」交学习过程 JSONL。

## 这套环境在做什么

工作台是「左手册、右实践」的双栏：左栏实验手册带**可折叠目录**；右栏从上到下是**本机终端**和「**实验报告 / AI 导师**」页签。

- **在本机跑实验。** 终端默认填好该 Lab 的验证命令，可直接编辑，也可从手册复制后粘贴（支持多行按顺序执行）；点「运行」即在你的机器上执行，输出实时回传。运行成功（退出码 0）会**自动记录为验证证据**。
- **实验报告就地写。** 固定五段模板（目标与准备 / 过程记录 / 问题与解决 / 思考题与发现 / 收获与反思）：终端输出可一键插入「过程记录」；填写「收获与反思」后保存即完成本层复盘；随时可导出 Markdown，或点「请导师点评」让 AI 检查报告。
- **导师只提问，不代写。** 要完整代码会被护栏挡下并转成任务分解；每次提问都会被归类（概念澄清 / 现象描述 / 追因分析 / 对比迁移 / 实验验证 / 索要答案）。左栏当前阅读位置会随提问送给模型，它能顺着你正读的内容追问。
- **完成即解锁。** 一次成功运行 + 一次带反思的报告保存，即解锁下一个 Lab。
- **过程留痕。** 所有交互按 `interaction-event` v1 契约存在本机浏览器，可随时导出 JSONL；评分只在[教师端](/guide/teacher-report)呈现，不干扰学习。

> 终端依赖本机导师服务（`npm run tutor`）。出于安全考虑：只允许运行 `cargo / make / qemu-system-riscv64 / rustc / rustup / rust-objcopy`，不支持 shell 语法（管道、重定向、`&&` 等），同一时间只允许一个运行中的命令，超时 5 分钟自动终止。

## 需要本地模型吗

不需要也能用。没有连上模型时导师退化为**离线引导**：按阶段给出固定的追问策略，护栏、事件记录、验证与复盘全部照常工作。

想接真实模型时，在 `os-lab/handbook` 下另开一个终端：

<CopyCommand command="npm run tutor" />

工作台顶部的连接状态按钮可以随时重新探测。

## 模型怎么配置

**在工作台界面上配置**：进入任意 Lab 工作台（如 [Lab1](/learn/lab1)），点击右上角的 **齿轮按钮（模型设置）**，填写三项：

| 设置项 | 说明 |
| --- | --- |
| 接口地址 | OpenAI 兼容 base URL；本机 Ollama、vLLM 或云端 API 均可，如 `http://127.0.0.1:11434/v1` |
| 模型名 | 如 `qwen2.5:7b`、`deepseek-chat` |
| API Key | 云端 API 需要时填写；本机 Ollama 留空 |

保存后立即重连生效。配置只保存在**本机浏览器**（localStorage），随每次提问发给本地导师服务转发，不会写入仓库；换设备需重新填写。全部留空 = 使用默认的本机 Ollama `qwen2.5:7b`。

服务端只保留少量运维项，用环境变量控制（一般不需要动）：

| 环境变量 | 默认值 | 说明 |
| --- | --- | --- |
| `OS_LAB_TUTOR_PORT` | `8787` | 导师服务监听端口 |
| `OS_LAB_TUTOR_DATA_DIR` | `os-lab/learning/sessions/` | 学习事件 JSONL 落盘目录（已 gitignore） |
| `OS_LAB_TUTOR_ORIGIN` | dev 端口 5173 | 允许的前端来源，逗号分隔 |

### 填了 API 还是「离线引导」？按顺序检查

1. **导师服务在跑吗？** 浏览器不直连你的 API，而是经本机导师服务转发。必须先在 `os-lab/handbook` 下运行 `npm run tutor` 并保持它开着。设置弹窗里若显示「导师服务未启动」，就是这一条。
2. **接口地址完整吗？** OpenAI 兼容地址一般以 `/v1` 结尾（如 `https://api.deepseek.com/v1`）。弹窗显示「上游返回 404」通常是地址少了 `/v1`。
3. **API Key 对吗？** 弹窗显示「上游返回 401/403」说明 Key 不对或没权限。
4. **网络通吗？** 「连接上游超时」多为网络/代理问题；本机 Ollama 则确认 `ollama serve` 在运行、模型已 `ollama pull`。

保存设置后弹窗会实时显示探测结果与失败原因，修好后点「保存并重连」即可。

前端连接哪个导师服务由 Vite 环境变量 `VITE_OS_LAB_TUTOR_ENDPOINT` 决定（默认 `http://127.0.0.1:8787`），改端口时在 `os-lab/handbook/.env.local` 中写：

```text
VITE_OS_LAB_TUTOR_ENDPOINT=http://127.0.0.1:8788
```

教学提示词全部在 `os-lab/tutor/prompts/` 下按文件管理：`system.md`（教学边界）、`labN/context.md`（各 Lab 上下文）、`stages/stage-*.md`（阶段策略）、`guardrails.yaml`（护栏规则，前后端共用同一份）。改完重启 `npm run tutor` 生效。
