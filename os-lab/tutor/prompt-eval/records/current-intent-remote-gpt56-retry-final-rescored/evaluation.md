# gpt-5.6-luna 真实模型评测（有效运行）

## 运行范围

- 模型：`gpt-5.6-luna`
- 接口：教师统一配置的 OpenAI-compatible `/v1` API；API Key 只注入评测子进程环境，未写入命令行、记录或仓库。
- 语料：V3 固定 19 条，覆盖七类本轮问题意图和三组“同一问题处于不同存储阶段”的不变性用例。
- 策略对照：完整意图策略 vs. 移除意图策略层、保留 system/Lab/证据/RAG 的基线。
- 有效性：18 条需要模型的用例均为 `remote`，1 条直接索要补丁由答案护栏拦截为 `guardrail`；19 条基线均有真实模型正文。所有请求和基线均一次成功。

原始线上回复、证据快照和首次评分见相邻的 `../current-intent-remote-gpt56-retry-final/raw.json`；本目录是依据修正后的 V3 评分规则对该冻结输入的本地重放，不重新调用模型。

完整策略优势出现在 `concept-sepc-debug`、`debug-panic-transfer` 和 `transfer-multicore`；基线优势出现在 `concept-sepc-reflect`。这是一轮温度 `0.3` 的抽样，效应很小，不能据此声称意图策略对真实模型存在稳定优势。后续应至少固定同一模型、温度和语料再运行 2 次，报告三轮均值、离散度和逐题正/平/负分布。

## 评分修正与真实问题

- 评分修正：拒绝式护栏话术不再因包含“完整实现/可直接提交”被算作答案泄漏；“思考：...”被识别为明确的可执行推理任务。修正后，`topic-switch-page-table` 的可执行性恢复为通过，主分从首次机器分的 94 更新为 96。
- 真实待优化：`concept-sepc-reflect` 仅给出概念解释，没有给学生一个下一步判断或验证动作，因此可执行性为 0。这与“无论在哪个阶段，都应引导学生继续思考”的目标不符，应在 concept 策略中要求解释后补一个问题或阅读/验证动作。
- 评分标定待优化：多个 concept/debug 回复的真实教学动作正确，但未命中 V3 用例给定的窄关键词，导致 `guidanceCorrectness=79`。不能仅为提高分数扩张正则，应先用人工标注核对这些例子，再决定扩展规则、增加语义判定或调整 gold patterns。

## 上游兼容性修复

本次真实运行发现并修复三项评测/连接问题：

1. `/models` 仅返回 HTTP 200 不足以证明是 OpenAI-compatible API；现在必须可解析为含 `data` 数组的 JSON，站点根地址返回 HTML 会提示检查 `/v1`。
2. 该网关要求 Chat Completions 请求显式传 `stream: false` 才返回 JSON；消融直连已对齐生产请求。
3. 离线回归原来的 `500ms` 连接窗口会误杀真实上游；真实地址默认 30 秒，`429/5xx`、空正文和 `mode=offline` 最多退避重试 3 次，并记录 `attempts`。
