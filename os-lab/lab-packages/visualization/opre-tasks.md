# OPRE 小任务（观察—预测—运行—解释）

成员 A · 第 4–5 周。每个任务 5–10 分钟；写入报告「过程记录」即可作为证据。

## Trap 视图 · T-OPRE-1

| 步骤 | 学生动作 |
| --- | --- |
| 观察 | 打开一次 Lab2 带 trace 的运行，数 `trap_enter` 条数 |
| 预测 | yield 循环 5 次时，`trap_enter` 会明显多于 5 吗？为什么？ |
| 运行 | `lab2` + `trace-edu` 受信命令 |
| 解释 | 对照 hello/power/yield 各自 syscall 次数，解释多出来的 trap |

**通过标准**：解释中区分「用户 ecall」与「可能的其它 trap」；若数据不足以区分，须写明「未观察到」。

## 调度视图 · S-OPRE-1

| 步骤 | 学生动作 |
| --- | --- |
| 观察 | 标记第一次与第五次 `Yield round` 邻近的 `task_switch` |
| 预测 | debug 未修（yield→Exited）时，switch 次数与 Yield 行数关系 |
| 运行 | 对比参考实现与未修 debug（或教师提供的失败 artifact） |
| 解释 | 用状态机说明为何提前 `All user apps exited` |

**通过标准**：明确写出「让出 ≠ 退出」；禁止只写退出码。

## 调度视图 · S-OPRE-2（衔接 fill）

| 步骤 | 学生动作 |
| --- | --- |
| 观察 | fill 空白时 panic / 无法轮转的现象 |
| 预测 | `find_next_task` 恒返回 None 时时间线长什么样 |
| 运行 | 实现后重跑，确认 Yield×≥5 |
| 解释 | 说明是否更新 `current` 对后续 trap 找 TCB 的影响 |

## 页表视图 · P-OPRE-1（Lab3）

| 步骤 | 学生动作 |
| --- | --- |
| 观察 | （有 walk trace 时）一次成功用户取指的三级路径 |
| 预测 | 去掉用户页 U 位后，失败停在哪一级/何种 fault |
| 运行 | 最小改动或教师 debug 变体 |
| 解释 | 对照 PTE 标志与 OSTEP 权限检查叙述 |

**降级**：若尚无 page_walk 事件，本任务改为「阅读 `mm.rs` 映射代码 + 预测 + 用输出断言验证未破坏 Lab2 用户程序」——须在报告标注「视图未就绪，使用源码降级」。

## 页表视图 · P-OPRE-2
