# 可视化教学规格（成员 A · 第 4–5 周）

> 目标：规定 Trap / 调度 / 页表三类视图**必须呈现的状态**与教学问题，供成员 B 实现、成员 C 提供 trace。  
> 原则：只画真实 trace 能支撑的状态；缺数据时显示「未观察到」，禁止用假动画补全。

## 共同规则

1. 每个视图绑定 `runId`；关闭 `trace-edu` 时视图为空态说明，不伪造。
2. 时间轴以 trace 事件顺序为准，不允许前端重排「更好看」。
3. Trace 作为服务端运行证据保留，学生界面通过测试断言和运行记录消费结果，不再提供独立 Trace 面板。
4. A 验收标准：若删掉某一必需状态，学生无法回答对应教学问题，则视图不合格。

## 视图 1：Trap 时序（Lab2 主视图）

### 必须呈现的状态

| 状态字段 | 含义 | 典型来源 |
| --- | --- | --- |
| `hart` / 时间序 | 事件先后 | `trap_enter` 序列 |
| `cause` | 陷入原因（至少区分 syscall / 其它） | trace 字段或推导 |
| `sepc`（若采集） | trap 时 PC | 可选扩展 |
| `from_mode`→`to_handler` | U→S 进入处理 | `trap_enter` |
| 对应源码锚点 | `trap.asm` / `trap_handler` | 静态映射表 |

### 教学问题（必须能回答）

1. 这次 trap 是用户主动 `ecall` 还是别的异常？
2. 处理返回后，下一条用户指令应是什么关系（结合 `advance_sepc`）？
3. 若连续两次 `trap_enter` 之间没有 `task_switch`，更像单任务 syscall 还是调度？

### 禁止简化成的错误心智

- 「trap 就是函数调用」——必须保留特权级切换语义。
- 「所有输出之间都发生了 trap」——UART/SBI 路径与用户 ecall 要可区分（若暂不可分，文案须写明局限）。

## 视图 2：任务状态时间线（Lab2 主视图）

### 必须呈现的状态

| 状态字段 | 含义 |
| --- | --- |
| `task_id` | 当前/切换涉及的任务 |
| `from` / `to` | 切换两端 |
| 任务状态（若可得） | Ready / Running / Exited |
| 与输出对齐 | `Yield round` 等用户可见事件可标注到邻近 switch |

### 教学问题

1. 为什么从任务 A 切到任务 B（对应哪次 yield/退出）？
2. 若 `Yield round` 只有 1 次却出现 `All user apps exited`，时间线上应看到什么异常模式？
3. fill 变体「从不更新 current」会在时间线上留下什么可疑模式？

### 禁止

- 把协作式调度画成「固定时间片硬抢占」而不加说明。
- 用平滑动画掩盖「未采集到 switch」的空洞。

## 视图 3：Sv39 page walk（Lab3 主视图）

### 必须呈现的状态

| 状态字段 | 含义 |
| --- | --- |
| VA / VPN2,1,0 | 地址切分 |
| 当前级 | L2/L1/L0 |
| PTE 有效与否 | 该级是否继续 |
| 叶标志 | R/W/X/U（至少 U 与 X） |
| 失败级 | 若 fault，停在哪一级 |

### 教学问题

1. 拒绝发生在哪一级？证据是哪一个 PTE？
2. 用户取指失败更像缺 X 还是缺 U？
3. 换任务后 walk 的根 PPN 是否变化（satp）？

### 禁止

- 画成「一次魔法翻译」而无三级。
- 在没有 page_walk trace 时用教材示意图冒充本次运行结果。

## 实现状态（成员 B · 第 4-5 周）

- 原学生端 Trace 回放组件已移除；服务端 Trace 采集、查询、完整性校验和可信断言保持不变。
- 终端继续隐藏原始 `TRACE_V1` 帧；历史 `trace_inspected` 事件仍由服务端兼容和校验。
- 页表视图暂未实现：真实 trace 无 `page_walk` 事件，按本规格保持可信空态，不伪造视图数据。
- 后端 `GET /runs/:id/trace` 查询接口属成员 C 第 4-5 周任务，继续作为运行证据与兼容接口保留。

A 的验收：学生能仅凭真实事件、统计、时间线和源码锚点回答对应教学问题；任一问题缺少真实数据支撑则打回。
